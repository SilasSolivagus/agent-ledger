# agent-ledger

看清楚你的编码 agent 到底做了什么——**实时轨迹**、**逐条账本**和**真实花费**。Claude Code、Codex、Cursor、WorkBuddy 四家通用。

Claude Code 和 Codex 都会把每次会话完整写在你本机上，但都没给你一个看它的地方。你只能在终端里往回滚，滚到哪算哪。这个工具把那些记录读出来，画成一次会话的完整轨迹和一张总账。

**全程只读本地文件，不上传任何内容。**

## 用

```sh
npx runledger serve
```

浏览器自己会打开，然后你就可以不管它了。

**它是监视器，不是历史浏览器。** 基线落在你按回车那一刻，之前的东西默认不显示——所以第一屏是空的，那是对的。你回去照常干活，轨迹每 5 秒自己冒出来。想往回看就点侧栏的窗口：`今天` `近 7 天` `近 30 天` `全部`。基线会落盘，关掉再开接着看，`--fresh` 重新划线。

npm 上叫 **runledger**（`agent-ledger` 被一个同赛道的包挡住了），装完之后命令行是 `agent-ledger`。

不需要配置，不需要 API key，不需要改你 agent 的任何设置。它读的是这两个目录：

| 来源 | 位置 | 能给出什么 |
|---|---|---|
| Anthropic · Claude Code | `~/.claude/projects/**/*.jsonl` | 全部，含 skill / 子代理归因 |
| OpenAI · Codex | `~/.codex/sessions/**/*.jsonl` | 全部，无归因字段 |
| Anysphere · Cursor | `~/.cursor/projects/**/agent-transcripts/**/*.jsonl` | 逐条事件；**无时间戳、不报 token** |
| WorkBuddy | `~/.workbuddy/workbuddy.db` | 仅会话级元数据与上下文占用 |

**装了哪个就出现哪个**，按目录存不存在判断，闲着的显示 `—`。一个都没有时页面会告诉你它找过哪些位置。

后两家给不出的东西，页面上会明说「这个来源不记录」，**不会显示成 0**——零是"测过、结果是零"的意思，那是另一回事。

左边一列是厂商 tab，每家一块自己的板子——安静的那家不会被忙的那家挤掉。最上面是**跨厂商**，把两家放在同一把尺子上量。点侧栏任一会话，右边出现它的完整轨迹。

**列会话不读文件，只有你点开的那个才被解析**，解析完按文件修改时间缓存——所以一千多个会话也开得动，正在写入的那个会自动重读。窗口拉宽到「全部」时 `--limit` 每个来源各封顶，**被挡下多少页面会说出来**。

其他命令：

```sh
agent-ledger serve --port 5000 --limit 100   # 换端口 · 每个 agent 各读最近 100 个
agent-ledger serve --no-open                 # 不自动开浏览器
agent-ledger serve --redact                  # 只上形状，不上内容（录屏/演示用）
agent-ledger serve --fresh                   # 丢掉上次的基线，从现在开始看
agent-ledger sessions                        # 列出能看到的会话
agent-ledger report --out ledger.html        # 导出一个自包含 HTML 文件
agent-ledger report --redact --out safe.html # 导出一份可以给别人看的
```

`report` 把读到的**每一个**会话都画进同一个文件，按时间倒序。默认 40 个会话大约 2 MB——要小一点用 `--limit`。

服务只绑 `127.0.0.1`，不监听外部地址。

## 看到什么

**一张总账**——固定负载、缓存命中率、首 token 中位数、累计输入输出、步数、工具调用次数。

**每次会话的轨迹**——一根发丝线是一步，圆点大小是这一步的耗时，方块是工具调用。一眼能看出工作集中在哪一段，不用读任何数字。

**逐条事件账本**——你说了什么、模型做了什么、调了哪个工具、拿到什么结果，按轮次分段。Claude Code 和 Codex 都有。你说的话有黑色标记，工具调用有土黄标记，模型的思考退到灰色——**几百行里眼睛知道往哪落**。

**每一条请求花了多少钱**——按该型号的四档单价（新鲜输入 / 输出 / 缓存读 / 缓存写）实算。行上、会话上、汇总上各一份。算不出来的会说明原因（型号只写了别名、或价目表里没有这一款），**绝不显示 ¥0**。价目表内置、不联网，`npm run prices:check` 负责发现上游变了。

**两家各自长什么样**——最上面那个「跨厂商」tab，把两家放在同一把尺子上量，而且跟着你选的时间窗走。**它不是排名**，原因写在下一节。

生成的页面**完全自包含**：没有脚本、没有字体 CDN、没有远程样式表。断网双击照样打开。

## 为什么没有「谁更好」

会话记录里有：发出去多少 token、回来多少、走了几步、调了哪些工具、花了多久。

会话记录里**没有**：答得好不好、活是不是真干完了、你有没有骂一句然后重问一遍。

所以「性价比」在这里算不出来——分子不存在。任何把两个 agent 排出名次的数字都是编的。

能诚实做的是把指标分成两组，界线画在页面上：

**怎么干活**——一步里并发几个工具、多少步是纯说话不动手、每次工具调用摊几步、参数多大、缓存命中。这几个数几乎不随任务大小变，是两家 harness 的设计差异，**可以直接比**。

**花了多少**——每步上下文、每步输出、每轮步数、每轮输出、每轮墙钟。这几个数几乎全由「你拿它干什么」决定。你用 Codex 修脚本、用 Claude Code 重构整个仓库，两边的「一轮」根本不是一回事，**差异就不是它们的差异**。只看，别当结论。

## 一个必须知道的事

**生成的 HTML 里有你的真实工作内容**——命令、文件路径、对话原文、模型的思考。

本地自己看没问题，**但不要随手发给别人或传到网上**。本仓库的 `.gitignore` 已经排除了 `examples/*.html`，就是为了防止误提交。

要给别人看就加 `--redact`。

## --redact 到底删了什么

它**不是**扫描敏感词然后打码。那种做法只会在漏掉一个的时候害你——它已经告诉你这页是安全的了，所以你才发了出去。

它做的是**整段丢弃正文，只留形状**：每一行还在、轮次还在、轨迹还在、数字一个不动，但你说的话、模型说的话、命令原文、文件路径、工具返回，全部换成 `··· 142 字`。工作目录和 git 分支直接删掉——路径带着你的账号名和客户项目名，分支名常常就是需求标题。

**故意保留的**：工具名（`Bash`、`exec_command`、`apply_patch`）。它们是轨迹的实质，且不含你的内容。**唯一要知道的例外**：MCP 工具名可能带内部服务名（`mcp__yourcompany__xxx`）。介意的话就别分享这一页。

脱敏在数据模型上做、不在 HTML 上做——否则每加一个模板就是一个新的漏点。测试的方式是往两种记录格式的**每一个**能装内容的字段里埋一个唯一标记，渲染完断言一个都搜不到。真实数据上验过（1.3 MB、25 个会话的报告）：home 路径 787 处 → 0，命令原文 192 处 → 0，分支名 38 处 → 0，而 606 个工具名、77 个轮次标记、25 条轨迹原样保留，总账数字一个没变。

## 图表的一条规矩

每个标记代表一个明确的单位，**单位印在图上**（`一格 = 2,500 TOKEN · 每五格一个点`）。你可以数格子自己验算。

一根你没法核对的柱子只是一块颜色。

颜色只用来区分**类别**（谁说的话），从不用来表示**数量**——数量一律用长度和明度表达。

## 现在还缺什么

诚实清单：

- **`report --out` 落后于看板**。导出页现在只有总账和逐条轨迹，看板上那五张图、跨厂商对比、产出归因都还没有。这是目前最大的一块欠账。
- **没有按项目配对的对比**。真要拿两家比同一件事，只能挑两边都干过的项目分别看，现在还得手动挑。
- **价目表是手抄的**。只写了实际会用到的型号，跟着版本更新；`npm run prices:check` 会告诉你上游动了没，但它不会自己改。非美元的条目（DeepSeek 按元计价）上游验不了，得手工核。
- **没有筛选和搜索**。会话表按时间排，一千多个会话里找特定的那个只能靠肉眼。
- **「会话跨度」不是模型耗时**。会话记录里没有单步耗时，这个数是相邻两条记录的时间差累加，中间包含工具执行和你去喝咖啡的时间。真的模型耗时要走 `record` 代理才量得到。
- **固定负载需要代理才能测到**。会话记录里不含请求信封（system prompt + 工具 schema），所以「每次请求固定携带多少」这个数字需要 `agent-ledger record` 走一次代理才有。**注意：Claude Code 的订阅登录态（OAuth）不允许走自定义 base URL，会被服务端拒绝**，这条路只对 API key 用户可用。（例外：Codex 的 rollout 里其实存了 `base_instructions` 全文，只是没有工具 schema，所以只能算出一半——现在没用它，免得和 Claude 侧的完整数字放进同一张图里比。）

## 开发

```sh
pnpm install && pnpm run check   # 构建 + 100 个测试
```

代理相关的测试是重点：它站在人和他们付费使用的模型之间，所以「字节原样透传」「我们的 bug 绝不能变成用户的报错」必须被验证，而不是写在注释里。

服务端的重点是另外三条：**URL 里的 id 永远不会变成文件路径**（只在已列出的文件里比对，没有可拼接的东西）、**正在写入的会话必须被重读**（缓存看 mtime）、**解析出错不能把服务带走**。

脱敏的测试是三条里最要紧的一条，理由和写法见上面那节。

跨 agent 的口径也必须被测：**OpenAI 把缓存 token 算在 `input_tokens` 里面，Anthropic 算在它旁边**（1514 个真实样本里 `cached ≤ input` 无一例外）。适配器统一换算成「`input` 只含新鲜输入」，否则 Codex 的缓存部分会被数两遍，两家的命中率不在一个尺度上——修之前 Codex 显示 47.9%，修之后 91.9%。

Codex 适配器的测试全都对着它和 Claude Code 不一样的地方：`session_meta` / `turn_context` 的字段直接挂在 payload 上、没有内层 `type`；harness 会以 `role: user` 往对话里塞 AGENTS.md 和 `<environment_context>`，只有 `event_msg/user_message` 才是人真的按了回车；`apply_patch` 发的是原始补丁而不是 JSON 参数；文本块叫 `output_text` 不叫 `text`。这四条每条踩中一次，账本就少一截或者多一截。
